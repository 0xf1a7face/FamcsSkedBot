# Экономия запросов Cloudflare: расписание и цвета

На `famcs.online` запросы идут на `/api/*` того же домена. Локальный API —
`http://127.0.0.1:8787/api`; на preview-доменах используется прежний `workers.dev`.
Расписание хранится в KV, пользовательские цвета — в D1 (`miniapp_colors`).

Цвета проверяются раз в десять минут в видимой вкладке и при возвращении фокуса,
если последняя проверка старше минуты. Правки отправляются через три секунды.
После ошибок интервал повторов растёт до пяти минут. Неподтверждённые изменения
сохраняются локально до успешного ответа; PUT со старой revision отклоняется.

## Публикация

В `pkgs/worker-api/wrangler.toml` используется Worker Route `famcs.online/api/*`.
Он не должен заменяться маршрутом на весь домен: статику продолжает отдавать Pages.
Перед публикацией проверяйте TypeScript, тесты API и frontend. Публикуйте API,
затем сайт обычным для проекта способом и проверьте результат сборки Cloudflare.
Локальный запуск не публикует изменения.

Для проверки маршрута используйте `GET /api/colors`: без авторизации ожидается
JSON с HTTP 401, если секрет `TELEGRAM_BOT_TOKEN` настроен. HTML означает попадание
в SPA fallback Pages; HTTP 503 с ошибкой конфигурации означает отсутствие секрета.
Не записывайте токен бота или Telegram initData в логи.

## Локальные проверки

```powershell
node --test pkgs/frontend/tests/*.test.mjs
node --test pkgs/worker-api/tests/*.mjs pkgs/worker-api/tests/*.cjs
node --check pkgs/frontend/app.js
cd pkgs/worker-api
npx.cmd tsc --noEmit
```

После публикации проверьте загрузку расписания, сохранение цветов и перенос
изменений между устройствами, включая повтор отправки после потери сети.
